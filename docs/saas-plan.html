Allaqachon bajarildi

Qo'llanmaning 20-bo'limi birinchi amaliy harakat sifatida uchta ishni ko'rsatadi. Ikkitasi bajarildi; uchinchisi — shu hujjat.

  1. Repo backup tayyor
    Loyihada git umuman yo'q edi — ya'ni qo'llanma talab qiladigan "har feature uchun bitta commit" va rollback tayanadigan hech narsa yo'q edi. Git yaratildi, auditdan o'tgan holat mainga baseline commit qilindi, ish saas-foundation branchida boradi. Arxiv nusxasi ham saqlandi.
  2. CLAUDE.md tayyor
    16-bo'limdagi matn, shu repoga moslashtirilgan: haqiqiy papka tuzilishi, haqiqiy tekshirish buyruqlari va 563 testlik baseline — regressiya endi o'lchanadigan bo'ldi, da'vo emas.

    Shu hujjat. Keyingi qadam sizniki.
01

Hozirgi arxitektura va qayta ishlatiladigan modullar

Lumen — Next.js 16 App Router, React 19, Prisma 7, Tailwind 4, Zod 4. TypeScript qattiq rejimda. 22 ta marshrut, src/lib ostida 16 ta domen moduli, 18 ta ma'lumot modeli.

Qayta yozilmaydi — qo'llanma ham shuni talab qiladi

  • Oltita agent: ATLAS, PULSE, SCOUT, MUSE, ORBIT, ASCEND va assistant + router.
  • Agent runtime — qayta urinish, timeout, abort, schema validatsiyasi, run yozuvi.
  • ProjectContextBuilder — agentga faqat so'ralgan kontekstni yig'adi.
  • Provayder abstraksiyasi — mock, Gemini, Groq, OpenRouter, Anthropic.
  • Dizayn tizimi va komponent kutubxonasi.

Poydevor uchun uchta kuchli tomon

  • Har bir yozuv allaqachon projectId olib yuradi va undan cascade bo'ladi. Ko'p loyihalarda eng og'riqli ish shu — bu yerda tayyor.
  • Yozish yo'li bitta: 51 ta Server Action. Mijoz yozadigan REST API yo'q, ya'ni qayta himoyalanadigan ikkinchi sirt yo'q.
  • AgentRun allaqachon provider, model, token, latency va attempts yozadi — 10-bo'lim talab qilgan 14 maydondan 7 tasi bor.
Bir kishi = bir hisob

Siz jamoa emas, bitta hisob tanladingiz. Shunga qaramay Workspace va Membership modellari qo'llanmadagidek qoladi: hozir har workspace'da aynan bitta OWNER bo'ladi. Bu qo'shimcha ish emas — limit, billing va izolyatsiya baribir bitta scope'ga bog'lanishi kerak. Keyin hamkasb qo'shish kerak bo'lsa, bu schema o'zgarishi emas, UI qo'shilishi bo'ladi.

Mavjud schema'ga tegishlar

  • Project ga workspaceId qo'shiladi. Qolgan 17 ta jadval unga projectId orqali yetadi — bu qo'llanmadagi "ishonchli parent relation".
  • Beshta JSON ro'yxat ustuni String dan String[] ga o'tadi; src/lib/json-list.ts olib tashlanadi.
  • 30 ta Json ustun Postgres'da jsonb bo'ladi — kod o'zgarmaydi.
  • To'rtta ilova darajasidagi toLowerCase() taqqoslash mode: "insensitive" ga o'tadi.
  • Settings singleton qatordan workspace'ga bog'lanadi.
  • AgentRun ga 7 maydon qo'shiladi: workspaceId, userId, featureKey, estimatedCostUsd, idempotencyKey, promptVersion, schemaVersion.

Ko'chirish tartibi va qabul mezoni

  • SQLite fayl va schema backup qilinadi; eski baza o'chirilmaydi.
  • Idempotent import skripti mavjud barcha yozuvlarni founder workspace'iga bog'laydi.
  • Tekshiruv: eski va yangi row count mos; orphan yo'q; har yozuv to'g'ri workspace'da; foreign key butun.
  • DATABASE_URL commitga, browserga va logga tushmaydi.
04

Auth va workspace ruxsat oqimi

Supabase Auth SSR, sessiya cookie orqali. Server foydalanuvchi identityni token'dan chiqaradi — browser yuborgan userId yoki workspaceId ga hech qachon ishonmaydi.

Bitta kirish nuqtasi

  • requireUser() — sessiyani tekshiradi, yo'q bo'lsa rad etadi.
  • requireWorkspace() — Membership orqali a'zolikni tasdiqlaydi va { userId, workspaceId, role } qaytaradi.
  • requireProject(projectId) — loyiha shu workspace'ga tegishliligini tekshiradi.
  • Har bir Server Action va Route Handler shundan boshlanadi. Proxy yoki UI guard yetarli emas — bu Next.js'ning o'z tavsiyasi.
Eng xavfli topilma

getActiveProject() hozir cookie yo'q bo'lsa butun bazadagi eng oxirgi tahrirlangan loyihaga qaytadi. Bitta kompyuterda bu qulaylik. Ko'p ijarachida esa: cookie'siz kirgan foydalanuvchi begona odamning biznesini ochadi — parol to'g'ri, sessiya haqiqiy, lekin ma'lumot boshqasiniki. Bu fallback workspace bilan chegaralanmasa, boshqa hech qanday tekshiruv yordam bermaydi.

Signup oqimi

  • Email tasdiqlangandan keyin User, Workspace va OWNER Membership bitta transactionda yaratiladi.
  • Xato xabari hisob bor-yo'qligini oshkor qilmaydi.
  • activeWorkspaceId cookie faqat tanlov — har so'rovda a'zolikka qarab qayta tekshiriladi.

Rollback

  • main branchi — auditdan o'tgan, 563 testi yashil ishlaydigan holat. Har doim qaytish mumkin.
  • Har feature bitta commit — bittasini revert qilish qolganiga tegmaydi.
  • Baza: migration'dan oldin dump; SQLite fayl o'chirilmaydi; import idempotent, ya'ni qayta yurgizsa dublikat yaratmaydi.
